# Internationalization (i18n)

The game is designed to be played in any language. This document is both the
developer reference and the translator guide.

## Principles

- Every player-visible string is identified by a **key** (`hud.tile.terrain`)
  and looked up at runtime. C code never contains player-visible text.
- **English (`en.lang`) is the reference**: every key must exist there. It is
  also the fallback when a translation is missing.
- Lookup order: active language → English → the key itself (so a missing key is
  visible on screen, and logged once, instead of crashing).
- Text is UTF-8 everywhere.

## Language files

One file per language in `assets/lang/`, named after the language code:
`en.lang`, `fr.lang`, `pt_BR.lang`... (ISO 639-1 language, optional `_` + ISO
3166 country). The system locale is matched as `language_COUNTRY` first, then
`language`.

```ini
# Comment lines start with '#'.
language.code = fr
language.name = Français
language.plural_rule = zero_one_other

# The value below is a non-breaking space (U+00A0), invisible here.
format.thousands_separator =  
format.decimal_separator = ,

hud.speed = Vitesse : {0}×
```

Rules:

- One `key = value` per line. Spaces around `=` and at both ends of the value are ignored.
- Keys: lowercase ASCII letters, digits, `_`, `-`, separated by `.`.
- Escapes in values: `\n` (new line), `\t` (tab), `\\` (backslash), `\s`
  (a regular space, useful at the start or end of a value).
- Non-ASCII characters are written directly (UTF-8), including non-breaking
  spaces (U+00A0), which are *not* trimmed.
- Duplicated keys are reported; the last one wins.

### Metadata keys (required in every file)

| Key                           | Meaning                                                    |
|-------------------------------|------------------------------------------------------------|
| `language.code`               | Must equal the file name (checked by the tests)            |
| `language.name`               | Native name, shown in the language selector                |
| `language.plural_rule`        | `one_other`, `zero_one_other` or `other_only` (see below)  |
| `format.thousands_separator`  | Digit grouping separator (`,` in English, U+00A0 in French) |
| `format.decimal_separator`    | `.` in English, `,` in French                              |

## Placeholders

Values may contain positional placeholders `{0}` to `{9}`, replaced at runtime.
Translators may **reorder** them freely, which is why sentences are never built
by concatenation:

```ini
# en: {0} = day, {1} = season, {2} = year, {3} = hours, {4} = minutes
hud.date = {1} {0}, year {2} · {3}:{4}
# fr
hud.date = {1}, jour {0}, an {2} · {3}h{4}
```

A translation must use exactly the same set of placeholders as the English
text (checked by the tests). Write `{{` and `}}` for literal braces.

## Plurals

A plural key has one entry per plural form, with a `.one` / `.other` suffix:

```ini
hud.debug.trees.one = {0} arbre sur la carte
hud.debug.trees.other = {0} arbres sur la carte
```

The form is chosen with the language's `language.plural_rule`:

| Rule             | "one" is used for | Languages (examples)                    |
|------------------|-------------------|-----------------------------------------|
| `one_other`      | 1                 | English, German, Dutch, Spanish, Italian |
| `zero_one_other` | 0 and 1           | French, Brazilian Portuguese             |
| `other_only`     | never             | Japanese, Chinese, Korean (only `.other` needed) |

Languages with more forms (Polish, Russian, Arabic...) need new rules: extend
`PluralRule` in `src/core/i18n.h` (with tests) when such a translation is added.

## Developer API (`src/core/i18n.h`)

```c
const char *title = tr("game.title");

char line[128];
TR_FORMAT(line, sizeof(line), tr("hud.tile.position"), x_text, y_text);

char count_text[32];
tr_integer(count_text, sizeof(count_text), tree_count);           /* "2,858" / "2 858" */
TR_FORMAT(line, sizeof(line), tr_plural("hud.debug.trees", tree_count), count_text);

tr_decimal(value_text, sizeof(value_text), 1.5, 2);                /* "1.50" / "1,50" */
```

- Keys in static tables are marked with `N_("terrain.soil")` and translated
  later with `tr(def->name_key)`.
- Format numbers with `tr_integer` / `tr_decimal`, never with `%d` / `%f`
  directly (identifiers such as seeds are the exception).
- `tr()` returns a pointer owned by the catalog: valid until the language
  changes. Do not keep it across frames; copy it if needed.
- Developer-facing text (logs, command line usage, fatal startup errors) is
  English only and never translated.

## Automated checks

Run by `ctest` (label `i18n`):

- `translations_<code>`: compares each language file with `en.lang`: missing
  keys, unknown keys, placeholder mismatches, `language.code` vs file name.
- `translation_keys_used_in_code`: every literal key passed to `tr()`,
  `tr_plural()` or `N_()` in `src/` exists in `en.lang`.

## Adding a language

1. Copy `assets/lang/en.lang` to `assets/lang/<code>.lang`.
2. Set the metadata keys, translate every value (keep the placeholders).
3. Re-run CMake configure (the new file is picked up automatically) and `ctest -L i18n`.
4. Launch with `--lang <code>` and check that every screen fits and renders
   (press L in game to cycle languages).

## Fonts and scripts

The bundled font (DejaVu Sans) covers Latin, Greek and Cyrillic scripts.
Languages using other scripts need:

- **CJK**: a font with the required glyphs (e.g. Noto Sans CJK) and font
  selection per language.
- **Arabic, Hebrew, Indic scripts**: complex text shaping and bidirectional
  layout: build SDL3_ttf with HarfBuzz (`SDLTTF_HARFBUZZ`, currently disabled
  in `cmake/Dependencies.cmake`).
